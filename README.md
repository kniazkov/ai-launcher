# AI Launcher

Локальные модели через Ollama: установка, настройка, обычный чат и работа с кодом через Continue CLI. Linux и WSL2, x86_64 и ARM64. Один Bash-скрипт на модель, общая реализация на Python без сторонних Python-пакетов.

## Быстрый старт

Склонируй репозиторий:

```bash
git clone https://github.com/kniazkov/ai-launcher.git ~/ai-launcher
```

Выбери каталог для больших файлов. **`install` по умолчанию устанавливает в текущую папку**, независимо от расположения исходного скрипта:

```bash
mkdir -p /mnt/d/ai
cd /mnt/d/ai
bash ~/ai-launcher/models/qwen3-coder-30b.sh install
```

Для Linux вместо `/mnt/d/ai` можно использовать, например, `~/local-ai`. Запускай от обычного пользователя. Если не хватает системных зависимостей, скрипт вызовет пакетный менеджер через `sudo`. Интернет нужен для установки.

Появятся каталог `.ai-launcher` с программами, моделями и настройками и каталог `bin` с командами запуска. Следующие команды не требуют исходного клона репозитория:

```bash
# Чат, без самостоятельного чтения файлов
bash /mnt/d/ai/bin/qwen3-coder-30b.sh chat

# Настройки только этой модели
bash /mnt/d/ai/bin/qwen3-coder-30b.sh configure --context 16384 --max-tokens 2048

# Работа с кодом именно в текущей папке
cd /mnt/d/Projects/my-project
bash /mnt/d/ai/bin/qwen3-coder-30b.sh code
```

Не запускай `install` из папки исходников проекта, если не хочешь хранить там веса моделей. Для нового диалога или работы с кодом используй `chat` / `code`, а не установку.

## Модели

Названия скриптов одинаковы в `models/` репозитория и в `bin/` готовой установки.

| Скрипт | Тег Ollama | Примерный размер весов |
| --- | --- | ---: |
| `qwen2.5-coder-7b.sh` | `qwen2.5-coder:7b` | 4,7 ГБ |
| `qwen2.5-coder-14b.sh` | `qwen2.5-coder:14b` | 9 ГБ |
| `qwen2.5-coder-32b.sh` | `qwen2.5-coder:32b` | 20 ГБ |
| `qwen3-8b.sh` | `qwen3:8b` | 5,2 ГБ |
| `qwen3-14b.sh` | `qwen3:14b` | 9,3 ГБ |
| `qwen3-coder-30b.sh` | `qwen3-coder:30b` | 19 ГБ |
| `qwen3-coder-next.sh` | `qwen3-coder-next` | 52 ГБ |
| `gpt-oss-120b.sh` | `gpt-oss:120b` | 65 ГБ |
| `qwen3-coder-480b.sh` | `qwen3-coder:480b` | 290 ГБ |

Это размеры конкретных сжатых тегов, а не требования к RAM. Во время работы дополнительно нужна память под контекст и вычисления. Маленький сервер с 6 ГБ RAM, на котором уже работают Java и база, не подходит для запуска большинства этих моделей вместе с приложением. Размер тегов может меняться в реестре.

Можно установить несколько моделей в один каталог: Ollama, Node.js и Continue общие, профили отдельных моделей независимы. Пример:

```bash
cd /mnt/d/ai
bash ~/ai-launcher/models/qwen3-8b.sh install
bash ~/ai-launcher/models/qwen3-14b.sh install
```

Для `code` модель должна поддерживать вызов инструментов. Launcher проверяет `capabilities` через API Ollama. Если конкретная сборка, например Qwen2.5 Coder, не объявляет `tools`, `code` завершится с объяснением; `chat` продолжит работать. Наличие одинаковой команды не добавляет модели отсутствующих возможностей. Поддержка инструментов также не гарантирует качество правок.

## Четыре команды

### `install`

```bash
bash /путь/к/models/qwen3-coder-30b.sh install
```

1. Проверяет системные команды и при необходимости устанавливает пакеты через `apt-get`, `dnf`, `yum`, `zypper` или `pacman`.
2. Устанавливает Ollama, локальный Node.js 22 и Continue CLI в `.ai-launcher` текущего каталога.
3. Скачивает выбранную модель, создаёт её профиль и переносимые команды в `bin`.
4. Останавливает временный сервер Ollama.

Системные пакеты (Python, curl, tar, zstd, xz, git, iproute, util-linux, сертификаты) ставятся в стандартные каталоги ОС: пакетный менеджер не умеет установить их все внутрь папки AI Launcher. Модели, локальные Node.js/Continue/Ollama, npm-кеш и рабочие временные файлы располагаются в папке установки. Ollama может создавать небольшой служебный каталог `~/.ollama`; сам дистрибутив WSL не переносится.

Повторный `install` **сохраняет настроенные параметры** и пропускает уже установленные программы/модель. Установка не является командой обновления. Continue зафиксирован на `1.5.47`, версии исходной рабочей конфигурации. При первой установке Ollama берётся с официального download URL, Node.js — последний выпуск ветки 22 с проверкой SHA256. npm проверяет целостность пакетов; lock-файл остаётся в установке. Источники загрузки: ollama.com (возможны редиректы на GitHub/CDN), реестр моделей Ollama, nodejs.org, registry.npmjs.org и зеркала пакетного менеджера. Скрипты не отключают проверку TLS.

Установка всех девяти моделей автоматически не выполняется. Скачивается только модель выбранного скрипта.

### `configure`

Показать текущие настройки:

```bash
bash /mnt/d/ai/bin/qwen3-coder-30b.sh configure
```

Изменить отдельные значения, сохранив остальные:

```bash
bash /mnt/d/ai/bin/qwen3-coder-30b.sh configure \
  --context 32768 --max-tokens 4096 --temperature 0.2 --threads 8
```

| Параметр | По умолчанию | Значение |
| --- | ---: | --- |
| `--context` | 8192 | Контекст: инструкции, история, код и ответ. Ограничен максимумом выбранного семейства. |
| `--max-tokens` | 1024 | Бюджет генерации одного ответа; больше нуля и не более половины контекста. |
| `--temperature` | 0.2 | Случайность генерации, от 0 до 1. |
| `--threads` | 0 | Число CPU-потоков Ollama; 0 — автовыбор. |
| `--timeout` | 1800 | Таймаут запроса, секунды. |
| `--load-timeout` | 600 | Ожидание загрузки весов Ollama, секунды. |

Размер окна не резервирует его весь для исходников: часть занимают инструкции Continue и описание инструментов. Большой контекст увеличивает расход памяти и задержку. На CPU больше потоков не всегда означает быстрее. Контекст и лимит ответа применяются и к чату, и к Continue.

Профиль хранится в `.ai-launcher/profiles/<модель>/settings.json`. Из него при каждом запуске генерируется `continue.yaml` (JSON-синтаксис, допустимый в YAML). **Правь параметры через `configure`, а не сгенерированный файл.** Для Continue создаётся локальный производный тег `ai-launcher-<модель>:latest` с теми же параметрами: даже если версия Continue читает контекст из метаданных Ollama, значения совпадут. Веса используются общие, повторно не скачиваются. Не нужно отдельно менять переменные Ollama или YAML. Пока сессия работает, менять конфигурацию нельзя: сначала выйди из неё. Неверная комбинация значений отклоняется без изменения файла.

### `chat`

```bash
bash /mnt/d/ai/bin/qwen2.5-coder-7b.sh chat
```

Текстовый чат через API Ollama; `/bye` завершает, `/clear` очищает историю. Текущая папка не даёт модели доступ к её файлам. История чата хранится в памяти процесса и не восстанавливается после выхода. При переполнении контекста Ollama может отбросить старые сообщения; этот простой чат не выполняет автоматическое резюмирование. Для длинного диалога используй `/clear` или увеличь контекст. Если модель возвращает отдельный поток thinking, он выводится перед ответом.

### `code`

```bash
cd /путь/к/репозиторию
bash /mnt/d/ai/bin/qwen3-coder-30b.sh code
```

Continue получает **текущую рабочую папку**, даже когда launcher установлен в другом месте. В интерфейсе доступны ссылки на файлы через `@`. Начни с небольшой задачи: «Прочитай README и объясни структуру проекта, ничего не меняй».

Чтение разрешено, изменения требуют подтверждения. Shell-команды по умолчанию отключены; можно включить их с подтверждением. Инструменты Fetch и UploadArtifact отключены:

```bash
# Чтение без инструментов записи; это политика агента, не файловая песочница
bash /mnt/d/ai/bin/qwen3-coder-30b.sh code --read-only

# Команды сборки/тестирования с подтверждением пользователя
bash /mnt/d/ai/bin/qwen3-coder-30b.sh code --allow-shell

# Восстановить сессию этой модели в этом проекте
bash /mnt/d/ai/bin/qwen3-coder-30b.sh code --resume

# Диагностика без интерфейса; инструменты записи исключены
bash /mnt/d/ai/bin/qwen3-coder-30b.sh code --prompt 'Ответь только OK. Не используй инструменты.'
```

История Continue разделена по модели и абсолютному пути проекта. `--read-only` не разрешает shell даже при одновременном `--allow-shell`. Режимы `--auto` и встроенный `--readonly` Continue не используются: у них другая семантика приоритетов инструментов.

## Папки установки и проекта

Рекомендуемый способ — запускать скрипты из `bin` готовой установки: они автоматически находят свою папку. Можно переместить **весь** каталог установки вместе с `bin` и `.ai-launcher`.

При запуске исходных скриптов из клона репозитория `chat`, `code` и `configure` по умолчанию ищут установку в корне клона. Для установки в другом месте есть одинаковый для всех команд параметр `--home`:

```bash
cd ~/projects/shop
bash ~/ai-launcher/models/qwen3-coder-30b.sh code --home /mnt/d/ai
```

`--home` меняет только место хранения AI Launcher, не папку анализируемого проекта. `install --home /data/ai` явно переопределяет правило текущего каталога.

## Сеть, права и процессы

`chat` и `code` запускают Ollama и клиент в отдельном Linux network namespace, где поднят только loopback. Для этого используется `sudo unshare --net`, затем `runuser --pty` возвращает выполнение обычному пользователю. После установки для общения не нужен интернет; Ollama Cloud отключён. Автоматического перехода в сетевой режим при ошибке изоляции нет.

Это блокировка внешней **IP-сети этих процессов**, не полноценная песочница. Файловые права пользователя сохраняются; Unix-сокеты, другие локальные процессы и нестандартные интеграции — отдельная граница доверия. Агент не ограничен технически одной папкой проекта. Не подключай дополнительные внешние инструменты без проверки. Логи и история могут содержать код и должны храниться с подходящими правами.

При работе в контейнере или WSL с запрещёнными namespace запуск завершится ошибкой. Нужны Linux/WSL2 с поддержкой сетевых namespace, sudo и обычная учётная запись. GPU не обязателен; драйверы GPU скрипт не устанавливает. Пакетные ветки кроме Ubuntu/Debian требуют проверки на целевом дистрибутиве. Python — 3.9+; бинарные сборки Ollama/Node требуют совместимой современной glibc. Alpine/musl не поддерживается.

Одна установка допускает одну активную сессию: это предотвращает одновременную загрузку нескольких больших моделей. Для параллельных пользователей потребуются отдельные установки и достаточные ресурсы. Сервер слушает случайный локальный порт. При выходе launcher останавливает только созданную им группу процессов Ollama. Уже работающую системную Ollama он не использует и не останавливает.

## Диагностика

- После `configure` выведи настройки без параметров; в начале `code` launcher также показывает действующие лимиты.
- Если Continue пишет про 8K при установленном 32K, проверь путь установки и `.ai-launcher/profiles/<модель>/continue.yaml`. Если там тоже 32K, сохрани версию Continue и точную ошибку: внутренние ограничения его версии могут отличаться от конфигурации.
- Если интерфейс не реагирует, используй `code --prompt 'Ответь OK'`. Это показывает ошибки запроса без TUI.
- Если Continue просит аккаунт, не вводи облачный API-ключ для обхода: нужно проверить локальный конфиг и версию. Документация новых выпусков менялась, поэтому используется фиксированная версия.
- Лог каждого запуска Ollama создаётся отдельно: `.ai-launcher/logs/<модель>/<дата-время>-<pid>.log`. Он не затирается следующей сессией.
- При нехватке памяти снизь `--context`, используй меньшую модель и проверь `free -h`. Рост swap может резко ухудшить скорость. В WSL проверь лимит RAM в `.wslconfig`.
- Если загрузка была прервана, повтори `install`: Ollama умеет продолжать загрузку весов. Не удаляй общие модели для исправления одной настройки.

## Разработка и проверки

```bash
python3 -m unittest discover -s tests -v
bash -n lib/bootstrap.sh lib/netns.sh
for file in models/*.sh; do bash -n "$file"; done
```

Тесты проверяют независимость и валидацию профилей, сохранение настроек при установке, конфигурацию обоих клиентов, переносимость команд, рабочую папку агента, запросы чата, завершение дочернего сервера и команды пакетного менеджера на подставных процессах. Они не скачивают модели и не запускают настоящий inference. Для проверки на целевом сервере нужны `install`, `chat`, затем `code --prompt` и интерактивная работа с тестовым проектом.

Официальные справочники: [Ollama Linux](https://docs.ollama.com/linux), [Ollama API](https://docs.ollama.com/api/chat), [Continue configuration](https://docs.continue.dev/reference), [Continue permissions](https://docs.continue.dev/cli/tool-permissions).
